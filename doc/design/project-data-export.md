# 项目数据导出设计

## 1. 需求追溯

本设计关联 `REQ-T063`，当前任务记录 `TASK.md` 的 T063 是本次范围的事实来源；视觉基准为 [`prototype/09-import-export.html`](prototype/09-import-export.html)。本阶段只产出设计和契约草案，用户确认前不进入阶段 1。

覆盖：项目设置导出卡片、三种输出格式、备份四项范围、设置持久化、导出状态与错误处理。未覆盖：HTML/Markdown 导入、在线分享、远程存储、权限体系和历史数据脱敏规则的最终决策。

## 2. 现状与目标

当前 `IProjectDataExportService` 只生成 `ProjectDataExportPackageDto` 的 ApixPress JSON 备份，`ProjectDataExportRequestDto` 只携带项目和目标文件路径。项目设置已有导出入口和 `IFilePickerService.SaveProjectDataExportFileAsync`。

目标是把“收集数据”“渲染文档”“写入目标”和“界面状态”分开，使三种格式共享同一份按项目筛选后的导出模型，同时不破坏现有备份导入链路。

## 3. 契约引用

已有契约和阶段 0 草案见 [`CON-T063`](../contracts/project-data-export.md)。实现必须复用现有接口、用例、环境、历史 DTO，不在 ViewModel 内拼接数据库字段或复制 DTO 定义。

建议的导出请求由格式和范围组成：备份范围四项只对 `backup` 生效；HTML/Markdown 固定使用接口与目录。范围持久化属于项目设置，不写进导出请求历史，也不保存 token、密码等敏感字段。

## 4. 技术设计

### 4.1 数据流

```text
项目设置导出卡片
        |
        v
ProjectImportViewModel / ExportSettings
        | 读取并保存项目级格式、范围、最近输出位置
        v
IProjectDataExportService
        | 以 ProjectId 读取接口、目录、用例、环境、历史
        v
ProjectDataExportModel（按范围筛选、稳定排序）
        |------------------|-------------------|
        v                  v                   v
备份序列化器          HTML 渲染服务          Markdown 渲染服务
        |                  |                   |
        +------------------+-------------------+
                           v
                   文件/目录写入器
                           |
                           v
                 成功、取消或错误状态
```

### 4.2 服务边界

- `IProjectDataExportService` 负责校验请求、按 `ProjectId` 收集数据、应用范围、调用格式策略并返回结果；不负责 Avalonia 控件状态。
- 备份序列化器继续输出现有 `ProjectDataExportPackageDto` 形状，并在用户确认后扩展可选范围字段和 schema 版本。
- `IProjectDataHtmlRenderer` 只接收已经筛选和排序的导出模型，生成单个完整 HTML 文档；内嵌必要 CSS，不能读取数据库或环境服务。
- `IProjectDataMarkdownRenderer` 只接收同一导出模型，生成索引与目录文件计划；默认每个接口目录输出一个 `.md`，文件名由稳定 ID 加可读名称生成并做路径字符清理。
- 写入器负责目录创建、临时文件、原子替换、取消检查和写入异常包装。渲染器失败不得留下半成品。
- ViewModel 负责格式切换、勾选、调用文件/目录选择器、loading 和状态消息；不负责渲染 Markdown/HTML。

### 4.3 三种格式

| 格式 | 输出 | 范围 | 主要用途 |
| --- | --- | --- | --- |
| ApixPress 备份 | 一个 `.apixpkg.json` 文件 | 四项可选 | 迁移与恢复 |
| HTML | 一个 `.html` 文件 | 接口与目录 | 离线浏览与分享 |
| Markdown | 一个目录，含索引和目录 `.md` 文件 | 接口与目录 | Git 归档 |

HTML 文档包含项目标题、目录树、接口方法与路径、说明、参数、请求头、请求体示例和响应示例；缺失内容显示空态，不输出 `undefined`。Markdown 使用稳定标题层级、代码围栏和表格，接口顺序按目录路径、方法、名称稳定排序。

### 4.4 备份范围与持久化

四项范围分别映射：

1. 接口与目录：接口节点、目录路径、请求快照和接口文档元信息。
2. 请求用例：`RequestCaseDto` 中的 `http-case` 及其父接口关联。
3. 环境变量：项目环境、环境变量、激活环境标识；敏感值是否脱敏列为待确认项。
4. 请求历史：`RequestHistoryItemDto` 及请求/响应快照。

范围设置按 `ProjectId` 保存，默认接口与目录、请求用例、环境变量选中，请求历史不选中，与原型 09 一致。最近格式和最近输出位置只作为便利设置保存；用户取消选择时不更新最近位置。现有项目设置持久化入口优先复用，若没有合适字段，阶段 1 先补契约后再选择现有项目设置表/服务，不在本设计阶段直接新增迁移。

### 4.5 文件命名和路径

- 备份建议名：`<项目名>.apixpkg.json`，由现有保存文件选择器确认文件路径。
- HTML 建议名：`<项目名>.html`，由现有保存文件选择器确认文件路径。
- Markdown 建议目录：`<项目名>-docs`，由 `PickStorageDirectoryAsync` 选择父目录后创建输出目录；如目录非空，阶段 1 需提供覆盖/取消确认。
- 项目名、目录名和接口名统一做平台路径字符清理；清理后为空时使用稳定 ID。

### 4.6 兼容和空数据

- 读取旧备份时，缺少新增范围字段按空集合/默认值处理；现有导入 schema 检查继续生效。
- 当前项目没有接口时，三个格式仍生成可打开结果，包含项目标题和“暂无接口”说明。
- 选中范围没有任何数据时，备份保存空集合，HTML/Markdown 保留目录索引和空态说明。
- 父接口被筛选掉时，用例不单独导出，避免生成无法关联的孤儿用例。

## 5. 界面原型

### 5.1 正常态

```text
+--------------------------------------------------------------------------+
| 项目设置 / 导入数据                                                     |
+--------------------------------------------------------------------------+
| 导出数据                                                                 |
| 支持导出 ApixPress 备份，或 HTML / Markdown 接口文档                     |
|                                                                          |
| [ApixPress 备份] [HTML] [Markdown]                                      |
|                                                                          |
| [x] 接口与目录  [x] 请求用例  [x] 环境变量  [ ] 请求历史                 |
| 导出位置：上次保存目录（导出时再次确认）                  [导出项目数据] |
+--------------------------------------------------------------------------+
```

### 5.2 HTML / Markdown 状态

```text
+--------------------------------------------------------------------------+
| [ApixPress 备份] [HTML] [Markdown]                                      |
|                                                                          |
| HTML：单个静态 HTML 文件，包含接口目录与接口文档                        |
| Markdown：目标目录 / 索引 + 每个接口目录一个 .md                        |
|                                                              [导出 HTML] |
+--------------------------------------------------------------------------+
```

### 5.3 Loading / Empty / Error

```text
Loading: +----------------------------------------------------------------+
         | 正在准备导出数据...                         [取消]             |
         +----------------------------------------------------------------+

Empty:   +----------------------------------------------------------------+
         | 当前范围没有数据，将生成包含“暂无数据”的有效文档。              |
         |                                                  [导出]          |
         +----------------------------------------------------------------+

Error:   +----------------------------------------------------------------+
         | [!] 导出失败：无法写入目标文件。                  [重试] [取消]   |
         +----------------------------------------------------------------+
```

## 6. 交互与异常

1. 进入导出卡片时加载当前项目的持久化设置；加载失败显示错误但不阻塞其他设置页。
2. 切换格式时保留四项勾选状态；切到 HTML/Markdown 时隐藏或禁用备份范围，切回备份恢复选择。
3. 点击导出后先保存当前设置，再打开文件或目录选择器；用户取消直接回到空闲态并显示信息反馈。
4. 进入 loading 后禁止重复导出，允许取消。取消要向收集、渲染和写入链路传递 `CancellationToken`。
5. 文件写入失败、目录创建失败、渲染失败分别包装为用户可读错误；保留原选择状态并允许重试。
6. 历史为空时不报错；若响应正文过大，阶段 1/2 按现有历史限制或待确认策略处理，不在渲染器内隐式截断。
7. 写入成功后更新最近格式和位置，显示输出文件或目录及各范围计数。

## 7. 验收和测试计划

### 单元测试

- 格式和四项范围默认值、切换与持久化。
- 每个范围独立包含/排除，父接口筛选时不导出孤儿用例。
- HTML 渲染标题、目录、接口、参数、代码块、空态和 HTML 转义。
- Markdown 文件计划的稳定排序、路径清理、标题/代码围栏和空态。
- 旧备份缺字段的读取兼容、取消传播和错误包装。

### 应用层测试

- ViewModel 三格式切换、文件/目录选择取消、重复点击防抖、loading/error 成功状态。
- 四项设置按项目隔离并在重新创建 ViewModel 后恢复。
- 写入器失败不留下最终文件，成功后结果计数和最近路径正确。

### 界面与交付验证

- XAML 结构守卫覆盖三格式控件、四个勾选、状态区和导出按钮。
- 应用内 GUI 真机验证 09 原型对照：格式切换、范围勾选、取消、成功、空数据和错误提示。
- Release 构建、完整测试、独立输出目录运行；不把本阶段设计文档误报为功能已完成。

## 8. 决策记录与实现状态

原待确认三点已于 2026-09-25 随实现落地确认：

1. Markdown 采用“目录输出 + `README.md` 索引 + 每个接口目录一个 `.md`”；目录名 `<项目名>-docs`，目标目录非空时导出失败并提示，不做覆盖。
2. HTML/Markdown 输出接口与目录并附带请求用例示例（沿用请求用例交付清单 UC-10 的确认方向）；备份四项范围仅备份格式显示。
3. 环境变量与交付内容不脱敏（沿用请求用例交付清单“不改变当前显示方式”的确认）；请求历史按现有 `RequestHistoryItemDto` 原样（含响应快照）进入备份，默认不勾选。

实现边界：备份包新增 `Environments` / `History` 可选字段，schema 保持 `v1`，旧备份缺字段按空集合兼容；现有备份导入链路继续只恢复接口与请求用例，环境与历史的备份恢复不在本次范围。最终字段以 `ProjectDataExportFormat(s)`、`ProjectDataExportRequestDto`、`ProjectDataExportSettingsDto`、`IProjectDataHtmlRenderer`、`IProjectDataMarkdownRenderer` 等代码契约为准。
