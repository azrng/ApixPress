# 请求用例交付设计

## 1. 需求追溯

本设计关联 `REQ-T077`，覆盖 UC-07、UC-08、UC-09。项目完整备份继续使用现有项目数据导出入口；HTML/Markdown 文档只提供阅读和复制参考，不复用本交付包的可恢复导入能力。

## 2. 设计目标与边界

设计提供一个独立的“请求用例交付包”格式和导入流程。它只处理接口、请求用例和项目级环境，使用稳定来源标识恢复父子关系；不把导入后的数据库 ID、方法路径键或接口名称当作关联依据。冲突和活动环境默认规则已按用户确认落地。

## 3. 契约引用

字段和版本边界见 `CON-T077`。代码落地后，DTO 和服务接口成为最终事实来源，契约草案只保留来源链接和变更记录。现有备份契约 `CON-T063` 继续服务项目完整备份，不与本交付包混用。

## 4. 技术设计

### 4.1 交付包结构

交付包是 JSON 文件，顶层固定包含格式标识、格式版本、导出时间、来源信息、接口、请求用例和环境集合。实体之间只使用包内来源 ID 引用：

```text
RequestCaseDeliveryPackage
├── format = "apixpress.request-case-delivery"
├── schemaVersion = "apixpress.request-case-delivery.v1"
├── exportedAt
├── source
│   ├── projectId
│   ├── projectName
│   └── product
├── interfaces[]
│   ├── sourceId
│   ├── name / folderPath / method / path / description
│   ├── requestBody / parameters
│   └── selectedByUser
├── requestCases[]
│   ├── sourceId
│   ├── parentInterfaceSourceId
│   ├── name / tags / description / updatedAt
│   └── requestSnapshot
└── environments[]
    ├── sourceId
    ├── name / baseUrl / isActive
    └── variables[] (sourceId / key / value / isEnabled)
```

导出时 `source.projectId + sourceId` 构成稳定来源键；导入时为目标项目生成新的数据库 ID，并维护包来源键到目标 ID 的映射。接口改名不会改变来源 ID；来自不同项目但方法路径相同的接口也不会互相覆盖其父子关系。

### 4.2 选择与收集

交付入口复用接口树和请求用例树的数据源，但维护独立的选择状态：

1. 选中接口时收集接口定义；是否包含其下用例由请求用例选择状态决定。
2. 选中请求用例时自动选中并收集父接口；父接口在摘要中标记为“自动附带”。
3. 收集阶段校验每个请求用例的父接口和快照；缺父接口立即形成孤儿项并阻止导出。
4. 环境按当前项目全部环境收集，保留前置 URL、环境名、变量名和值、启用状态和活动标记；环境不绑定到单个请求 URL。
5. 所有集合按来源 ID、目录路径、方法和名称稳定排序，摘要显示接口、用例、环境和变量数量。

### 4.3 导入预览

预览只读取交付包和目标项目现有摘要，不写入数据库。为每个接口、请求用例和环境生成一条决策项，状态为：

- `新增`：目标项目没有匹配的来源键或业务键。
- `更新`：同一来源项目和来源 ID已存在，默认映射到原目标实体。
- `跳过`：用户选择不写入该项。
- `另存`：用户要求保留现有项并创建新目标实体。
- `孤儿`：请求用例引用的接口来源 ID不存在或被决策为不导入；默认阻止提交。

匹配优先使用来源键；来源不同但接口方法和路径、请求用例父接口和名称、环境名称和变量名发生冲突时，再按业务键生成冲突项。预览必须同时显示包来源项目、总数量和冲突数量。

### 4.4 冲突决策与目标 ID

默认决策采用非破坏性规则：同一来源键默认更新；不同来源的业务键冲突默认跳过；用户可逐项改为覆盖、跳过或另存。另存时沿用当前 `_copy` 规则，名称仍冲突则追加数字后缀。

接口先建立来源键到目标接口 ID的映射，再创建请求用例；请求用例的 `ParentId` 只从该映射取得。环境先建立来源键到目标环境 ID 的映射，变量通过目标环境 ID 和变量名写入。包内任何数据库 ID都不直接写入目标项目。

### 4.5 一次提交与回滚

导入服务按以下顺序在同一数据库事务内执行：

1. 重新校验包版本、来源引用、冲突决策和孤儿项。
2. 按决策写入或更新环境、接口及其参数。
3. 根据接口映射写入或更新请求用例。
4. 在目标项目已有活动环境时保留当前活动环境；没有活动环境时才应用包内活动标记。
5. 所有写入成功后提交事务并刷新项目树；任一异常、取消或关系校验失败均回滚。

预览和确认之间如果目标数据发生变化，提交前重新计算冲突；不能安全重放时返回“数据已变化，请重新预览”，不做部分写入。

### 4.6 失败边界和副作用

- 文件不存在、大小超限、格式版本不支持或 JSON 无法解析：预览快速失败，不访问写入仓储。
- 孤儿项、未决冲突或目标项目为空：显示可读错误或空结果；确认按钮保持禁用。
- 数据库写入失败、取消令牌触发或刷新失败：事务回滚，保留预览结果和错误信息，允许重试。
- 成功提交后仅刷新当前项目数据和状态消息，不改变其他项目。
- 交付包文件本身是用户选择的输出文件；导出失败不得留下看似完整的最终文件，应使用临时文件后原子替换。

### 5.1 请求用例交付入口

```text

+--------------------------------------------------------------------------+

|     [ ] 创建用户       [ ] 创建用户_管理员                              |
```


```text
Loading: | 正在分析交付包和目标项目...                         [取消]     |
Empty:   | 包中没有可导入的接口、请求用例或环境。               [关闭]     |
Error:   | 导入失败，已回滚本次变更：...                [重新预览] [关闭] |
```

## 6. 交互与异常

1. 导出入口与项目备份入口分开；进入交付入口时读取当前项目接口、请求用例和环境摘要。
2. 选择变化立即更新自动附带父接口和交付统计；没有选中项时禁用生成按钮。
3. 生成交付包使用临时文件和原子替换；用户取消文件选择不视为失败。
4. 导入先预览，预览期间不写入；用户关闭或取消时清除待导入决策。
5. 冲突决策必须逐项可改；存在孤儿项或未决项时禁用确认导入。
6. 确认导入时显示 loading，禁止重复确认，允许取消；取消或异常后显示回滚结果。
7. 成功后刷新接口树、请求用例节点、环境列表和计数，并显示本次新增、更新、跳过和另存数量。

## 7. 验收与测试计划

### 单元与应用层测试

- 选择接口、选择请求用例、自动携带父接口和空选择校验。
- 包格式版本、来源键、父子引用、稳定排序和历史响应排除。
- 环境和变量值收集、来源键映射、活动环境默认策略。
- 预览新增/更新/跳过/另存/孤儿分类和逐项决策。
- 同源更新、异源业务冲突、另存命名和重复导入。
- 事务成功提交、任一阶段失败回滚、取消回滚和预览后数据变化重算。

### 界面与交付验证

- XAML 结构测试覆盖独立入口、选择树、统计摘要、预览决策表和状态区。
- GUI 验证选择、自动附带、冲突切换、取消、成功、孤儿和失败回滚状态。
- 完整测试和 Release 构建；导入后重新加载并发送至少一个请求用例。
