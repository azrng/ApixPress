# ApixPress 整体 UI 视觉重设计方案

## 1. 需求追溯

本设计关联 `REQ-T088` 和 `TASK.md` 的 T088。本轮按用户明确要求实现首页卡片网格、项目拖拽排序与品牌色调整；其他桌面页面保留为后续统一视觉方向，不在本轮重排布局。

## 2. 现状审视

本次检查了 `design-system.yaml`、主窗口、首页、项目工作区、请求工作台、导入弹窗截图和 `doc/design/prototype/` 中的既有原型。

- 设计系统已经规定深色 Fluent、高信息密度和语义色；Avalonia、Semi.Avalonia、Ursa、AvaloniaEdit 也已具备，不缺 UI 框架或基础控件技能。
- 首页当前把标题区、工具栏和项目区分别包成大卡片，项目项内部又有多个视觉分组；既有 `01-home.html` 原型的项目项直接放在页面画布上，当前实现额外增加了表面层级。
- 用户提供的导入截图中，窗口内容连续出现来源块、说明条、模式切换块、状态条和 URL 卡片，彼此都使用较重的底色或边框。视觉边界数量超过信息层级本身，文字与操作显得拥挤。
- 请求工作台已有项目导航、接口树、上下文栏、请求配置与响应分区。主要问题应由表面、间距和标题规则的统一解决，不需要先改成另一种业务布局。
- 已有 13 个 HTML 原型覆盖主流程，可继续作为交互与状态基线；本次不另建一套平行组件库或复制 token。

## 3. 设计方向

### 3.1 视觉原则

1. 保留深色工作环境，以 `Brush.Background.App` 承载窗口底色，以 `Surface` 承载主要工作区，以 `Subtle` 表示轻量区分；相邻区域优先用间距和细分隔线组织，不为每一组信息再加一层卡片。
2. 品牌强调采用克制的青蓝色，用于主要操作、焦点和少量当前选择状态；请求方法、成功、警告和错误继续使用已有语义色，不把品牌色铺满整个导航和内容面板。
3. 每个页面只保留一个主要视觉焦点。标题、上下文、编辑内容和操作按稳定的阅读顺序排列；说明文字压缩到必要信息。
4. 重复对象（项目、接口、历史、用例）保留足够清晰的行或项边界；页面主体不再整体套入重复的“卡片中的卡片”。
5. 圆角和阴影回归层级用途：主要工作区使用 6–8px 轻圆角，输入框和行项使用更紧凑的形状；弹窗保持单一明确的前景层。最终数值更新到现有设计 token。
6. 动效仅用于悬停、按下、选择、加载和弹窗出现的状态反馈；不新增背景图、渐变装饰或营销式留白。

### 3.2 共用框架

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ [A ApixPress] [首页] [项目标签…] [+]       [环境/通知/设置] [窗口操作] │
├──────────────────────────────────────────────────────────────────────────┤
│ 页面内容：明确标题与当前上下文；主操作固定在标题或工具栏右侧              │
│                                                                          │
│ 工作区只使用必要的导航栏、树列表、编辑面板和响应面板                     │
├──────────────────────────────────────────────────────────────────────────┤
│ 状态栏：保存、发送、校验等短反馈                                         │
└──────────────────────────────────────────────────────────────────────────┘
```

顶部保留窗口操作和项目标签；应用标题、导航、环境与通知各自保持单一入口。状态栏继续承载已有反馈，不重复在页面标题下显示长段操作说明。

### 3.3 项目首页

目标：将首页从三层大卡片收敛为“标题与操作 + 项目列表”的清楚层级。保留项目项作为可点击的重复对象，但移除“点击卡片打开”这类重复提示。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 项目首页   本地工作区                               [搜索…] [+ 新建项目] │
│ 12 个项目                                                                 │
├──────────────────────────────────────────────────────────────────────────┤
│ [项目图标] 项目名称 [默认] [拖拽把手]   [项目图标] 项目名称 [把手]      │
│            项目备注                         项目备注                     │
│            打开项目 →                       打开项目 →                   │
└──────────────────────────────────────────────────────────────────────────┘
```

首页只显示项目总数，不显示已打开标签数量。项目卡片按容器宽度使用自适应多列网格；卡片尺寸由网格分配，不固定为 334px 宽。左侧拖拽把手在无搜索条件时可用，排序事务保存失败则还原视图顺序并显示错误反馈。空状态继续保留“新建项目”入口。

### 3.4 项目与请求工作区

目标：保留当前三段式导航关系（功能栏、接口树、主内容），减少主内容中的重复面板边框，并让 URL / 发送操作成为请求编辑首要焦点。

```text
┌────────────┬──────────────────┬─────────────────────────────────────────┐
│ 功能导航   │ 项目 / 接口树    │ 接口名称 [调试 | 文档]      保存状态   │
│ 接口管理   │ [搜索接口…]      │ [GET v] [URL 输入........................] [发送] │
│ 请求历史   │ ▾ 用户           │ [Params] [Body] [Headers] [Auth]        │
│ 项目设置   │   GET /users     │ 请求配置表 / Body 编辑区                │
│            │   POST /users    │ ───────── 可调整分隔线 ──────────────── │
│            │ ▾ 订单           │ 响应 [Body] [Headers] [实际请求] 200  84ms │
│            │                  │ 响应内容 / 空态 / 错误与重试             │
└────────────┴──────────────────┴─────────────────────────────────────────┘
```

功能导航与接口树保持稳定宽度，主工作区占用剩余空间。请求配置和响应继续沿用当前可拖动的上下分区；内容区至少保留一张主要表面，内部标签和表格通过轻分隔线组织。响应为空时保留现有发送提示，错误状态在响应顶部提供重试，不将提示嵌进额外的厚重卡片。

### 3.5 导入弹窗

目标：响应用户对两个框都应更大的反馈。扩大弹窗和可用内容区，固定底部动作；减少内部背景块，使 URL、历史列表和文件模式看起来属于同一个任务区域。

1440×920 参考尺寸约 920×680，最大宽度约 960px；小窗口按可用区域缩放并让正文滚动，底部操作固定。下列尺寸为设计目标，阶段 1 按窗口最小尺寸复核。

```text
┌────────────────────────────────────────────────────────────────┐
│ 导入数据                                                [关闭] │
│ [URL 导入] [上传文件]              自动识别 OpenAPI / Swagger │
│                                                                │
│ 文档地址                                                       │
│ [可编辑 URL........................................] [导入 URL]│
│   最近使用 ▾   选择后回填，可继续编辑                          │
│                                                                │
│ 文件模式时： [文件路径............................] [选择文件] │
│ 导入中 / 校验错误 / 成功摘要在这里就近反馈                      │
│                                                                │
├────────────────────────────────────────────────────────────────┤
│                                                  [取消] [继续] │
└────────────────────────────────────────────────────────────────┘
```

URL 历史仍保持为可编辑输入旁的下拉候选，不改保存和导入规则。冲突确认使用同一弹窗规格：冲突列表占主要内容区，覆盖/跳过采用清楚的单选项，警告只在选择覆盖时出现，取消与确认保持固定在底部。

### 3.6 页面状态

```text
Loading：在正在加载的区域显示进度与短文案；其余导航仍保持可读。
Empty：显示“当前没有内容”及一项最相关的创建、导入或清除筛选动作。
Error：在失败的区域展示原因和重试入口；保留用户已输入的 URL、参数或筛选条件。
Selected：用轻背景或边缘标识当前项；不要只用更亮的品牌色填满整行。
Focus：键盘焦点有可见边界，与 hover 状态区分。
```

## 4. 技术设计

- 继续使用 Avalonia 12.1.4、Semi.Avalonia 12.1.0.1、Ursa.Avalonia 2.2.0、AvaloniaEdit 和现有 MVVM 绑定。
- 不增加依赖。项目排序沿用 View → ViewModel → Service → Repository，SQLite 迁移 009 新增 `projects.sort_order`；拖拽命令只更新此字段，不影响默认项目、标签或请求数据。
- 颜色、间距、圆角、阴影沿用 `design-system.yaml` 的唯一规则文件；用户确认后先收敛现有 token，再逐页套用，避免局部硬编码和并行主题。
- 保持 Avalonia 编译绑定、现有状态绑定、Tab 顺序、右键菜单、弹窗关闭与键盘快捷键。

## 5. 实施与验收顺序

1. 本轮先验收品牌 token、首页信息层级、多列网格、项目拖拽排序和数据库升级兼容。
2. 后续再应用同一规则到项目导航、请求配置、响应面板、导入弹窗、历史、环境、用例和设置页面。
3. 在 1280×800、1440×920、1920×1080 下复核首页网格、文字裁切、焦点、空态和拖拽目标状态。
4. 对照现有命令绑定确认卡片打开、右键菜单、搜索与快捷键行为保持可用。

## 6. 待确认项

- 首页、项目顺序持久化和青蓝色品牌强调为本轮确认范围。
- 其余页面是否继续沿用 Apifox 工作流原型细化，留待逐页设计时确认。
