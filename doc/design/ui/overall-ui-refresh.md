# ApixPress 整体 UI 视觉统一方案

## 1. 需求追溯

本方案关联 `REQ-T089`。目标是在现有 API 开发工作流上统一视觉层级，不改变业务流程、数据和交互契约。既有 `doc/design/prototype/` 中 13 个原型继续作为流程与状态参考；其紫色主题不再作为视觉规范。

## 2. 现状审视

- 当前产品已经使用深色石墨背景和青蓝设计 token，但若干样式仍直接写入旧紫色值。例如 `DialogStyles.axaml` 中选择态边框仍用 `#667C6CF0`，导致主题资源与实际控件视觉不一致。
- 首页与导入窗口存在多层容器和较重边界。截图中的导入窗口把来源说明、模式切换、信息条和 URL 输入分别包成独立色块，主流程显得碎且拥挤。
- 项目工作区包含主窗口标签、功能导航、接口树、项目内标签、编辑器和响应区。分区本身符合复杂 API 工具的工作方式，但各层容器和圆角同时强调时会削弱当前任务焦点。
- 组件库和现有 token 已经足够支撑统一设计，不需要新增前端技能、框架或组件依赖。主要工作是明确表面层级并清理旧视觉值。
- 页面已有 loading、empty、error、选中和操作反馈的实现；本方案统一这些状态的视觉表达，不重写状态流转。

## 3. 技术与视觉决策

### 3.1 颜色、文字与表面

- 背景层：沿用 `Brush.Background.App`、`Surface`、`Subtle`。主内容放在自然画布上，只有确需强调的工作区或浮层使用表面底色。
- 品牌层：沿用 T088 的青蓝色 `#2FB6C5` / `#228F9C`。用于主要命令、键盘焦点和少量当前选择标识，不把整条导航或整块面板染成品牌色。
- 语义层：GET/POST/PUT/DELETE/PATCH 方法色和 HTTP 状态色保持现有定义。JSON key 的紫色只表示代码语法，不表示品牌状态。
- 文字层：沿用 Segoe UI 与 Microsoft YaHei UI；主体 14px、辅助信息 12–13px、页面标题 18–20px。URL、路径、耗时和 JSON 继续使用适合扫描的等宽或表格数字样式。
- 边界层：弱化大面积边框与阴影。常驻面板使用分隔线，悬浮对话框和菜单才使用明显的层级边界。
- 圆角层：建议把常用控件收敛到 4px，独立区域用 6px，窗口弹层最高 8px；普通列表项不做胶囊化。最终值在阶段 1 同步到 `design-system.yaml` 与 Avalonia 资源。
- 一致性：所有新增或调整的颜色、间距、圆角、阴影均经 `design-system.yaml` 和 `Assets/Styles/*.axaml` 资源引用，不在页面中写视觉常量。

### 3.2 主窗口与首页

```text
┌────────────────────────────────────────────────────────────────────────┐
│ A  ApixPress  │ 首页 │ 项目 A × │ 项目 B × │                 环境  设置 │
├────────────────────────────────────────────────────────────────────────┤
│ 项目首页                                    搜索项目…   [+ 新建项目]   │
│ 12 个项目                                                               │
│                                                                        │
│ [项目 A]              [项目 B]              [项目 C]                   │
│ 备注 · 最近使用      备注 · 最近使用      备注 · 最近使用              │
│                                                                        │
├────────────────────────────────────────────────────────────────────────┤
│ 状态反馈                                             当前环境：开发     │
└────────────────────────────────────────────────────────────────────────┘
```

首页沿用自适应多列网格和已实现的拖拽排序。标题与工具栏直接落在页面画布上；项目项是唯一需要稳定重复边界的表面。项目项中移除重复的“点击卡片打开”说明，让项目名和单击反馈承担入口作用。空状态沿用新建项目主操作，搜索无结果时提供清除搜索或新建入口。

### 3.3 项目工作区与请求编辑

```text
┌──────────────┬────────────────────┬─────────────────────────────────────┐
│ 项目导航     │ 项目 / 接口树      │ 接口名称       环境：开发          │
│ 接口管理     │ 搜索接口…          ├─────────────────────────────────────┤
│ 请求历史     │ ▾ 用户             │ GET  /users              [发送]     │
│ 项目设置     │   GET /users        │ Params  Body  Headers  Auth         │
│              │   POST /users       │ 请求编辑区                            │
│              │ ▾ 订单             ├──────── 可拖动分隔线 ────────────────┤
│              │                    │ 响应  Body  Headers  实际请求   200  │
│              │                    │ 响应内容 / 空态 / 错误与重试          │
└──────────────┴────────────────────┴─────────────────────────────────────┘
```

- 保留现有三段导航关系：功能入口、项目内容树、主工作区。视觉实现优先去掉重复壳层，不把这三个操作区合并成不清楚的单栏。
- 主工作区顶部先表达接口名和当前环境，其下是唯一高强调请求行：方法、URL、发送。保存和保存用例留在同一操作组但采用次级样式。
- 参数、Body、Headers、Auth 等维持现有标签和命令；编辑区域用轻量分隔组织，不为每个标签内容套卡片。
- 请求/响应继续使用当前可调整的分隔布局。响应头承载状态码、耗时与响应大小，正文区域提供空态、错误和重试状态。
- 接口总览继续使用表格行和现有方法颜色；行悬停与当前选中通过背景和左侧状态标识区分。

接口总览保留在主内容区，不再额外放入独立大卡片：

```text
┌ 项目功能栏 ┬ 项目 / 接口树 ┬ 接口管理             Auth   全部接口     │
│            │ 搜索接口…     │ GET      获取用户      /users/{id}       │
│            │ ▾ 用户        │ POST     新建用户      /users            │
│            │   GET /users  │ DELETE   删除用户      /users/{id}       │
└────────────┴───────────────┴──────────────────────────────────────────┘
```

### 3.4 历史、设置、环境与用例

```text
请求历史
┌────────────┬──────────────────────┬─────────────────────────────────────┐
│ 功能导航   │ 请求历史  搜索…      │ GET /users       200   84 ms        │
│            │ GET /users   10:24   ├─────────────────────────────────────┤
│            │ POST /orders 10:22   │ 参数 | Headers | 实际请求 | Body    │
│            │ GET /health  10:18   │ 请求快照 / 响应内容                  │
│            │                      │                                     │
│            │                      │ 选择记录后展示详情；空态保留提示      │
└────────────┴──────────────────────┴─────────────────────────────────────┘

项目设置
┌──────────────────┬─────────────────────────────────────────────────────┐
│ 设置分组         │ 当前设置标题                                          │
│ 基本信息         │ 项目名称     [...................................]   │
│ 导入数据         │ 项目备注     [...................................]   │
│ 导出数据         │                                  [保存 / 导入 / 导出] │
└──────────────────┴─────────────────────────────────────────────────────┘
```

- 历史主视图以可扫描的行/表格为主；详情区只显示当前选择记录，不额外嵌套多个大卡片。
- 设置采用“窄分组导航 + 单一表单画布”。字段标签、帮助文本、输入项和保存动作固定对齐；少量设置才不强制铺满宽屏。
- 环境与用例沿用右侧抽屉，标题、上下文、内容列表和操作区形成一致结构。抽屉中的重复项使用行，不层层再包卡片。
- 列表加载中保留导航和标题；无数据时给出与当前域对应的创建或导入动作；加载失败显示局部原因和重试。

```text
环境抽屉（右侧）                    用例抽屉（右侧）
┌────────────────────────┐         ┌────────────────────────┐
│ 环境管理          [+]  │         │ 请求用例     [保存当前]│
│ [开发] [测试] [生产]   │         │ GET  /users/{id}       │
│ 环境名称              │         │ [搜索用例…]            │
│ Base URL              │         │ 示例：正常用户         │
│ 变量名       值       │         │ 示例：缺少权限         │
│ [+ 新增变量]          │         │ [加载] [复制] [删除]   │
│ [保存该环境]           │         │                        │
└────────────────────────┘         └────────────────────────┘
```

导入/导出设置仍留在项目设置主内容区，弹窗只承载导入流程和冲突决策：

```text

基本信息       来源  [URL 导入] [文件导入]
导入数据       URL / 文件 [................................] [选择]
导出数据       最近来源 ▾   格式自动识别
               ─────────────────────────────────────────────
               导出数据
               格式 [ApixPress 备份] [HTML] [Markdown]

```

### 3.5 导入、冲突确认与通用对话框

```text
┌────────────────────────────── 导入数据 ────────────────────────────────┐
│ [URL 导入]  [上传文件]                                                 │
│ 文档地址                                                               │
│ [最近使用 ▾  https://service.example/openapi.json          ] [导入]   │
│ 文件模式时： [文件名...................................] [选择文件]    │
│ 状态与校验结果在对应输入下方就近展示                                   │
├────────────────────────────────────────────────────────────────────────┤
│                                                       [取消] [导入]     │
└────────────────────────────────────────────────────────────────────────┘

┌────────────────────────── 检查接口冲突 ────────────────────────────────┐
│ 将新增 1 个接口，更新 150 个接口；已保存用例会保留                     │
│ 方法   路径                              当前接口                      │
│ PUT    /api/CodeSystem/{id}              MDM API                       │
│ …                                                                      │
│ 处理方式  ( ) 覆盖现有接口   (•) 跳过同名接口                           │
├────────────────────────────────────────────────────────────────────────┤
│                                                       [取消] [确认更新] │
└────────────────────────────────────────────────────────────────────────┘
```

- 导入弹窗只保留标题、来源模式、输入/文件选择、就近反馈和固定底部动作。移除重复的来源卡、长说明条和 URL 外层卡片。
- URL 历史仍可下拉选择；选中只回填，输入可继续编辑。导入状态与格式校验在输入区域下方显示。
- 冲突列表占用弹窗主体空间，行高和列宽保证方法、完整路径及当前所属接口可读；覆盖/跳过使用紧凑单选项，危险影响只在选中覆盖时说明。
- 建议标准导入窗口约 920×660，冲突窗口约 1040×720；窗口可用区域不足时正文滚动，标题和底部动作保持可见。最终尺寸以 1280×800 实测结果为准。
- 确认弹窗按内容高度收敛；危险操作使用红色动作，不用品牌强调色表达危险。

### 3.6 公共状态与视觉反馈

| 状态 | 表现 |
| --- | --- |
| Loading | 原区域内轻量进度或骨架，不遮住无关导航；避免空白区和全屏遮罩 |
| Empty | 一句说明当前为空，最多一个主要创建/导入动作；过滤无结果提供清除筛选入口 |
| Error | 在发生错误的区域显示可读原因与可用重试/修正动作；保留用户输入 |
| Selected | 轻量表面色或细边缘指示；不以大面积高饱和品牌色填充 |
| Hover | 只在可操作项出现轻微背景变化，避免常驻边框 |
| Focus | 键盘焦点使用可见青蓝描边，与选中和悬停状态区分 |
| Disabled | 降低对比并保持布局尺寸稳定；必要时通过 Tooltip 说明禁用原因 |

## 4. 交互、边界与技术方案

- 所有现有导航、请求、保存、导入、导出、筛选、重试、键盘操作和数据行为保持原样；本阶段不创建新 DTO、状态或持久化字段。
- 页面调整时复用现有 Views、ViewModels、主题控件和 style class。只在真实重复且能减少维护成本时抽共享视图。
- 对话框内容超出最小窗口时正文滚动；固定操作栏不与滚动内容重叠。长路径、URL 和接口名保留省略提示或可复制能力。
- 关键交互至少覆盖鼠标与键盘焦点。拖动排序只在首页保持既有能力，不将拖拽扩展到其他列表。
- 阶段 1 先调整 token 与公共资源，再按框架/首页、请求工作区、列表/设置、弹窗/抽屉的顺序落地；每批检查公共样式的影响面。

## 5. 阶段 1 验收路径

1. 在 1280×800、1440×920、1920×1080 分别检查首页、请求编辑、接口总览、历史、设置和导入/冲突弹窗。
2. 检查搜索、标签、发送/取消、响应重试、导入历史回填、冲突处理、抽屉打开关闭、空态入口和键盘焦点。
3. 对照现有测试与命令绑定确认业务行为未变；样式改动至少完成受影响页面的 smoke test。
4. 保存上述关键页面截图供用户验收。阶段 1 结束后由用户确认视觉方向，再决定阶段 2 是否继续同一批次的业务/应用层调整；本需求预期无需阶段 2。

## 6. 待确认项

- 请用户确认是否接受“石墨深色 + 青蓝强调 + 减少嵌套卡片 + 保留三栏工作流”的整体方向。
- 请用户确认是否将 T089 覆盖的所有页面与常用弹窗一并纳入实施，还是先按首页、请求工作区、导入弹窗分批验收。
- 本设计未确认前不进入阶段 1，不修改界面代码或主题 token。
