# 项目数据导出需求

## 需求追溯

本需求由 `TASK.md` 的 T063 作为当前事实来源。仓库旧需求只提出“基础备份”，没有独立的稳定编号；本文件补充 T063 的可验证范围，不覆盖导入 HTML/Markdown。

## 目标与范围

项目用户可以从项目设置导出当前项目数据，满足迁移备份、接口文档分享和 Git 归档三类场景：

- ApixPress 备份格式：用于恢复项目数据；导出范围可分别选择接口与目录、测试用例、环境变量、请求历史。
- HTML：导出单个可离线浏览的静态接口文档。
- Markdown：按接口目录生成 Markdown 文档文件，适合纳入代码仓库。

HTML 和 Markdown 本期只导出接口目录及接口文档，不承担导入能力。

## 用户与入口

单机项目用户从“项目设置 / 导入数据”区域的“导出数据”卡片进入。导出始终限定当前项目，不跨项目读取数据。

## 业务规则

1. 格式只能是 ApixPress 备份、HTML、Markdown 三者之一。
2. 四项备份范围独立勾选；默认值由当前项目保存，并可在下一次导出时继续使用。
3. HTML 导出为单个静态文件；Markdown 导出为目标目录下的索引文件和目录文档文件。
4. 取消文件或目录选择不视为失败，不写文件、不改变项目数据。
5. 空范围允许导出，生成包含项目元信息和“暂无数据”说明的有效结果；不因没有接口而崩溃。
6. 导出失败必须保留设置页，显示可理解的错误状态，并允许重试。
7. 备份格式继续兼容现有 ApixPress 备份导入；HTML/Markdown 不在本期导入。

## 非功能要求

- 导出过程不能阻塞 UI；应提供 loading、可取消和完成/失败反馈。
- 文件写入采用临时文件或等价的原子替换策略，避免失败时留下看似完整的目标文件。
- 导出数据按当前项目隔离，不把其他项目的环境、历史或用例写入结果。

## 验收标准

- 三种格式均可从项目设置选择并导出。
- 备份格式能按四个范围开关包含或排除对应数据，且设置在重新打开项目后保持。
- HTML 可在无应用运行时打开并浏览接口目录、请求信息、参数、请求体和响应示例（有数据时）。
- Markdown 生成索引和目录文档，接口信息可被普通 Markdown 阅读器查看。
- 空数据、取消、写入失败、渲染失败、取消导出均有稳定状态和可测试结果。
- 现有 ApixPress 备份导入回归测试继续通过，旧备份缺失新增范围字段时按兼容默认值处理。

## 待确认项

- Markdown 是否确认采用“目标目录 + 索引文件 + 每个接口目录一个 `.md` 文件”，还是改为单个 Markdown 文件。
- HTML/Markdown 是否需要包含测试用例、环境变量和请求历史；当前设计按原型仅导出接口与目录。
- 请求历史是否包含响应正文；当前设计按现有历史 DTO 原样保留可用字段，具体脱敏策略需用户确认。
