# ApixPress 整体 UI 视觉统一

## 背景

用户反馈现有整体界面观感不理想，希望先重新审视并统一设计。此前 T088 只完成首页网格、项目排序和品牌色调整，工作区、导入弹窗、历史、设置与各类面板仍待统一。

## 目标与范围

面向本地 API 开发者和测试人员，统一窗口框架、首页、项目工作区、请求编辑与响应、历史、设置、抽屉和弹窗的视觉层级。保留桌面 API 工具所需的信息密度，让当前项目、请求上下文、主操作和结果状态一眼可辨。

纳入本次设计：

- 主窗口标题栏、项目标签、全局状态反馈。
- 项目首页、项目卡片和空状态。
- 项目功能导航、接口树、接口总览、请求编辑器、响应区和请求历史。
- 项目设置、导入导出页面、环境与用例抽屉。
- 新建、导入、覆盖冲突、删除确认等常用对话框。
- loading、empty、error、selected、hover 和键盘 focus 状态。

不纳入：请求和导入业务规则、数据模型、数据库、导航能力、快捷键、既有命令、权限、应用框架或 UI 依赖变更。设计以现有 Avalonia、Semi.Avalonia、Ursa 和 AvaloniaEdit 为基础，不要求迁移控件库。

## 用户与核心流程

用户从项目首页打开项目，在请求工作区配置并发送 API 请求，检查响应；也会导入接口文档、查阅历史、管理环境、用例和项目数据。

1. 在首页搜索、浏览或新建项目。
2. 在项目工作区选择接口或快捷请求，编辑方法、URL、参数、Headers、Body 和环境。
3. 发送请求，在响应区检查状态、耗时、响应内容或错误并重试。
4. 按需查看历史、管理环境与用例，或在项目设置中导入和导出数据。

## 关键对象与可见范围

沿用现有项目、API 文档、接口、请求用例、请求历史、环境和环境变量，不新增字段或改变含义。应用保持本地单用户模式，不增加角色、权限或跨项目可见规则。

## 视觉与交互要求

- 延续深色桌面工作台，不新增浅色主题。
- 采用石墨中性色作为底层、青蓝色作为唯一品牌强调；HTTP 方法色以及成功、警告、错误色保持语义用途。
- 页面背景、工作区表面、局部输入/编辑表面最多形成三个清晰层级。优先通过留白和细分隔线组织内容，不给每个信息组再套卡片。
- 每个页面突出一个主操作。次要操作使用中性按钮或图标命令；破坏性操作使用危险语义色。
- 保留请求工具需要的信息密度；标题、上下文、表单、表格和响应有稳定对齐与间距，长 URL、路径和名称可读或可提示全文。
- 选中、悬停、焦点、禁用、加载、空和错误状态有清楚且一致的视觉反馈。焦点不能只依赖鼠标悬停样式。
- 弹窗和抽屉按内容提供足够空间；内容较长时滚动，底部主要动作保持可见。

## 边界情形

- 小于目标尺寸时，正文滚动且固定操作仍可达；禁止通过裁切内容换取表面紧凑。
- 空项目、空历史、无用例、搜索无匹配和请求尚未发送时，保留与当前上下文匹配的提示。
- 加载失败、请求失败和导入校验失败在所属区域说明原因；不清空用户正在编辑的 URL、参数或表单。
- 长 URL、接口路径、项目名和错误内容不得覆盖相邻操作；被省略的文本能通过 Tooltip 或选择复制查看。

## 验收标准

- 主窗口、工作区、项目设置、历史、导入导出、抽屉和弹窗共享一致的背景、文字、边框、圆角、间距和按钮层级。
- 主内容不再被重复的外层卡片、内层卡片和说明条包裹；需要独立点击的项目、接口、历史和用例仍有清楚边界。
- 品牌强调统一为青蓝色，不残留与品牌冲突的紫色选择边框或主按钮；JSON 语法高亮中的紫色作为代码语义色保留。
- 首页项目网格、三栏项目工作区、请求/响应分区和设置表单在 1280×800、1440×920、1920×1080 下均可读，操作区域不挤压内容。
- 导入与冲突处理窗口能够清楚显示 URL/文件输入、历史选择、冲突列表、处理选项及固定底部操作，不裁切文本。
- 现有导航、按钮、菜单、请求、导入、保存、快捷键和数据行为保持不变。
- 实现阶段须提供首页、请求工作区、历史/设置、导入/冲突弹窗截图，并确认主要交互和关键状态。

## 当前假设与待确认项

- 当前设计方向：深色石墨底、克制青蓝强调，沿用 API 方法色和状态语义色。
- 页面范围按“整套桌面 UI”理解；实现时分批推进，但共用同一套视觉规则。
- 若用户没有额外品牌资料，保留现有字体家族和 Avalonia/Semi/Ursa 技术栈。
- 本需求与设计文档由用户确认后，才进入阶段 1 的界面实现。
