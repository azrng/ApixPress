# ApixPress 整体 UI 视觉重设计需求

## 需求追溯

本需求关联 `TASK.md` 的 T088。现有项目已具备首页、项目工作区、请求调试、接口文档、历史、设置和导入等功能。本轮先落实用户明确提出的首页项目布局、手动排序和 API 网关品牌色；其他页面沿用本设计方向逐步迭代。

## 目标与范围

让本地 API 开发者能够在 ApixPress 中快速找到项目、配置请求、查看响应，并明确感知当前项目、接口、环境和操作状态。统一窗口框架、页面表面、标题层级、间距和弹窗表现，降低重复边框与重复说明造成的视觉噪声。

覆盖范围：

- 应用标题栏、项目标签、全局状态栏。
- 项目首页和项目卡片列表。
- 项目工作区导航、接口树、请求配置、响应查看和请求历史。
- 项目设置、导入导出页面、环境与用例面板、常用弹窗和抽屉。
- 上述页面的加载、空、错误、选中、悬停和键盘焦点状态。

不覆盖：业务流程、数据模型、请求行为、持久化规则、快捷键、权限和导航能力变更；不要求新增控件依赖或重写应用框架。

本轮明确纳入：移除首页已打开标签数量；项目卡片按可用宽度自适应为多列；支持拖拽调整顺序并持久化到本地 SQLite；调整全局品牌强调色以适配 API 请求网关。HTTP 方法色及成功、警告、错误状态色维持原语义。

## 用户与入口

用户为单机使用 ApixPress 的 API 开发者或测试人员。用户从应用首页进入项目工作区，在同一窗口内完成接口配置、发送请求、检查响应、导入文档和管理项目数据。

## 页面与模块清单

| 页面或模块 | 用户目标 | 必须保留的现有能力 |
| --- | --- | --- |
| 应用框架 | 切换首页和项目，查看全局反馈 | 窗口操作、标签切换、状态提示 |
| 项目首页 | 搜索、浏览和打开项目 | 新建项目、默认项目标识、项目设置入口 |
| 项目工作区 | 切换接口管理、历史和项目设置 | 导航、接口树、项目内标签、环境入口 |
| 请求工作台 | 编辑并发送请求，查看响应 | 参数、Headers、Body、发送、保存、响应标签和重试 |
| 导入与导出 | 导入 OpenAPI / Swagger / Postman，导出项目数据 | URL 历史、文件选择、冲突处理、状态反馈 |
| 面板与弹窗 | 管理环境、用例、历史和项目设置 | 既有命令、校验、危险操作确认、关闭行为 |

## 核心使用流程

1. 用户在首页搜索或浏览项目并打开项目工作区。
2. 用户在未筛选的项目网格中拖动项目把手调整顺序；重新启动后顺序仍保留。
3. 用户从项目导航选择接口或创建快捷请求，配置参数、Headers、Body 和环境。
4. 用户发送请求，在响应区查看状态、耗时、Body、Headers 或实际请求；失败时使用重试入口。
5. 用户从项目设置导入文档，可在 URL 输入处选择历史地址，也可编辑为新地址；导入发现冲突时选择覆盖或跳过。
6. 用户在工作区内管理请求用例、历史和环境，获得与主工作台一致的层级、反馈和操作入口。

## 关键业务对象

沿用现有项目、API 文档、接口、请求用例、请求历史、环境和环境变量。首页项目排序新增项目顺序字段，通过 SQLite 迁移保存，不改变其他对象的字段含义和项目隔离范围。

## 权限与可见范围

沿用当前本地单用户模式，不增加角色、权限或跨项目可见规则。

## 边界场景与异常

- 页面加载期间仍显示区域级进度，不出现大块空白等待。
- 项目、接口、历史或用例为空时，说明当前状态并保留已有建议动作。
- 导入、发送、保存失败时，在相关内容附近展示可理解的原因与可用的重试或修正入口。
- 内容较长时提供滚动或省略提示，不能覆盖操作区、挤压相邻面板或裁掉重要文本。
- 键盘焦点、选中项和禁用状态必须可见，不依赖鼠标悬停识别操作。

## 非功能要求

- 保持桌面 API 工具需要的信息密度，优先保证可扫描、状态清晰和重复操作效率。
- 继续以深色 Fluent 桌面风格为默认方向；复用现有设计 token，并把色彩、间距和圆角的最终定义维护在唯一的 `design-system.yaml` 中。
- 使用现有 Avalonia、Semi.Avalonia、Ursa 和 AvaloniaEdit 组件；本需求不引入新的 UI 框架或组件依赖。
- 核心窗口在 1280、1440、1920 像素宽度，以及 800、920 像素高度下保持内容可读和操作可达。

## 验收标准

- 首页、工作区、导入弹窗共享一致的背景、表面、文字、边框和操作层级。
- 主要内容不再由重复的外层卡片、内层卡片和说明条层层包裹；重复项目项仍可保留清晰的独立点击区域。
- 主操作位置明确，次要说明不与主操作争夺视觉焦点；低频操作不重复占据内容区。
- 请求配置和响应区域在常见窗口尺寸下均可读、可调整；响应状态、失败说明和重试入口清晰。
- 导入弹窗拥有足够的内容宽高，URL 输入、历史地址、文件模式、冲突处理和底部操作不发生重叠或裁切。
- 首页不显示已打开标签数量；宽屏一行显示多个项目卡片，小窗口下仍可自适应为单列。
- 项目可通过明确的拖拽把手重排；搜索过滤时不开放拖拽；保存失败时恢复原顺序并显示反馈。
- 关闭并重新打开应用后项目顺序保持不变；旧数据库升级后沿用升级前的项目顺序。
- 原有按钮、菜单、标签、快捷键、请求行为和数据隔离保持不变。
- 设计阶段确认的页面状态均有明确布局；实现阶段通过 1280、1440、1920 宽度的桌面截图复核。

## 当前假设与待确认项

- 当前决定：保留中性石墨深色底，将品牌强调色调整为克制的青蓝色，表达网络连通与请求流转；HTTP 方法色及状态语义色不随品牌色改变。
- 当前假设：先统一主框架、首页、请求工作区和导入弹窗，再将同一规则应用到历史、环境、用例和设置面板。
- 待后续迭代：请求工作区、导入弹窗、历史、环境、用例和设置页面继续按本方案逐页收敛；本轮不扩大到这些页面的布局重写。
