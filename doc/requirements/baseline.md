# ApixPress 全局需求基线

> 原 `doc/requirement.md`（225 行）于 2026-11-08 按 doc-AGENTS 迁移规则拆分：§1-11 全局基线迁入本文件；§12/§13 两个功能域需求迁独立文件；原文件删除（git 历史可追溯）。

## 1. 项目背景

ApixPress 是本地单用户 API 联调工具（桌面端）：导入 OpenAPI 文档 → 管理接口 → 环境变量 → 发送调试请求 → 保存用例与历史。以「项目」为主要工作区单元，接口文档、环境、用例和请求历史默认随项目隔离。

## 2. 目标与范围

### 2.1 本期目标

- 支持多项目管理：首页项目列表 + 项目 Tab 并行打开，各自独立环境与工作状态
- 每项目多环境（BaseUrl + 变量），请求发送前解析 `{{变量}}` 占位符
- 请求编辑（方法/URL/Query/Path/Header/Body/Form-data 文件）→ 发送 → 响应查看（状态/耗时/大小/头/格式化内容）
- 用例保存/加载/复制/删除；请求历史按项目过滤
- 本地 SQLite 持久化，重启不丢

### 2.2 本期范围

导入（URL/本地文件）、接口树分组与搜索、快捷请求工作台、环境管理（双栏界面）、用例抽屉、请求历史、应用设置（外观/强调色切换）、检查更新与自更新。

### 2.3 非本期范围

登录与权限体系、云端同步、团队协作、全局变量/Vault Secrets、目录/拖拽/远程 URL 上传、上传进度与断点续传。

## 3. 用户角色

本地单用户（接口开发/测试/联调人员）；无权限体系。

## 4. 页面与模块清单

主窗口（首页 Tab + 项目 Tab + 顶部操作区）；首页项目列表（搜索/新建）；项目工作区（左侧接口导航、中央快捷请求编辑器、右上环境选择）；环境管理界面（环境列表/前置 URL/变量双栏）；导入对话框；用例抽屉；请求历史（列表+详情）；设置中心（含关于页检查更新）。

## 5. 核心业务流程

启动 → 默认项目（或创建引导）→ 打开项目 Tab → 选环境 → 编辑请求（变量解析）→ 发送（快照锁定）→ 响应 → 按需保存用例。

## 6. 关键数据与字段

`projects`、`project_environments`（base_url/is_active）、`environment_variables`（挂环境实体）、`api_documents`/`request_cases`/`request_history`（均含 project_id）；`RequestSnapshotDto`（含结构化 Form-data 文件字段）。

## 7. 权限与可见范围

本地单用户工具，无权限体系；本地凭据明文持久化策略维持已文档化口径。

## 8. 边界场景与异常

删除激活环境前先切换或自动指定；文件缺失/不可读 fail fast 并显示文件名；发送中仅保留取消；请求结束无论如何恢复编辑；OS 不返回本地路径时文件字段提示平台不支持。

## 9. 非功能要求

Avalonia 桌面应用（win-x64 自包含发布）；SQLite 版本化迁移；UI 组件优先复用 Ursa.Avalonia。

## 10. 待确认项

无（原 §12/§13 待确认项已随功能域文件收敛，其中 Tab 化相关拍板结论已进 DES-006）。

## 11. 当前假设

- 本地单用户工具，不引入登录和权限体系
- 本地数据持久化为主，暂不接入云端同步与团队协作
- 「项目」为主要工作区单元，数据默认随项目隔离
- 每项目至少一个可用环境，BaseUrl 为环境一级字段
- 每项目仅一个激活环境，切换即整体切换请求上下文
