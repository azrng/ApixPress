## 问题与建议

### 严重

#### 1. 密码明文存储

`ProjectHttpAuthSettingsEntity` 和 `ProjectHttpAuthSettingsDto` 中 `basic_password` 和 `bearer_token` 以明文存储在 SQLite 中。虽然这是桌面应用，但如果工作区文件被共享或同步到云盘，凭据会泄露。

**建议**：至少做 DPAPI / AES 加密，或在文档中明确警告。

#### 2. `BuildRequestSnapshotForSend` 每次发送都重新构建 Auth

`ProjectRequestWorkflowViewModel.cs`:

```csharp
private RequestSnapshotDto BuildRequestSnapshotForSend(RequestWorkspaceTabViewModel workspaceTab)
{
    var snapshot = workspaceTab.BuildSnapshot();
    return workspaceTab.IsHttpInterfaceTab
        ? _interfaceRoot.ApplyGlobalAuth(snapshot)
        : snapshot;
}
```

`ApplyGlobalAuth` 每次都重新 `BuildAuthSettings()` + `CloneSnapshot`，对于高频调试场景会有不必要的分配。

**影响**：不是 blocker，但高频使用时值得优化。

### 中等

#### 3. `RunMigrations` 中每次迭代都调用 `UpgradeLegacyWorkspace` + `MigrateLegacyWorkspaceData`

`DatabaseInitializer.cs`:

```csharp
for (var version = currentVersion + 1; version <= CurrentSchemaVersion; version++)
{
    connection.Execute(LoadMigrationSql(version));
    UpgradeLegacyWorkspace(connection);         // 每轮都跑
    MigrateLegacyWorkspaceData(connection);      // 每轮都跑
    RecordMigrationVersion(connection, version);
}
```

`UpgradeLegacyWorkspace` 执行了大量 `EnsureColumn` 和 `UPDATE` 语句，在 v1→v3 升级时会重复执行 2 次。对于已有大量 `request_cases` 的数据库可能很慢。

**建议**：将 `UpgradeLegacyWorkspace` 的调用移到循环外（仅执行一次），或按版本号条件执行。

#### 4. `ProjectRequestEditorViewModel.RefreshComputedState` 过于庞大

方法体约 80 行，包含 20+ 个 `SetComputedProperty` 调用。每次 config/response 变化都会触发完整刷新。

**建议**：按职责拆分为 `RefreshEditorModeState()`、`RefreshDocumentPreviewState()`、`RefreshRequestCodeState()`，减少不必要的属性刷新。

#### 5. `ProjectInterfaceRootWorkspaceViewModel.RefreshHttpInterfaces` 全量重建

每次 `_savedRequests` 变化都 `.Select(...)` 创建新的 `ProjectHttpInterfaceOverviewItemViewModel` 列表，如果 `savedRequests` 数量大（数百接口），这会有性能问题。

**建议**：增量更新而非全量替换。

#### 6. `AppUpdateRunner` PowerShell 路径注入分析

`EscapeForPowerShell` 仅替换单引号为 `''`：

```csharp
private static string EscapeForPowerShell(string value)
{
    return value.Replace("'", "''");
}
```

路径通过单引号包裹注入到 PowerShell 脚本中。虽然路径来自内部逻辑而非用户输入，单引号内 `$()` 和反引号不展开，所以这个实现实际上是 **安全的**。建议加一行注释说明安全性分析。

### 低

#### 7. `IsInterfaceRootWorkspaceActive` 同步逻辑分散

`SyncInterfaceRootWorkspaceStateWithActiveTab()` 在 `ActiveTabChanged` 和 `EditorState` 两个 flag 下都被调用，可能导致重复设置。`OnIsInterfaceRootWorkspaceActiveChanged` 又调用 `Shell.NotifyWorkspaceStateChanged()`。

**影响**：不影响正确性，但调试时容易产生循环通知困惑。

#### 8. `BuildSnapshot` 不再临时修改 `RequestName`

旧代码先改 `ConfigTab.RequestName` 再改回来，新代码通过 `requestNameOverride` 参数传递。这是正确改进，但需确认旧路径的所有调用者都已更新。

#### 9. `BatchObservableCollection` 替换

`EnvironmentPanelViewModel`、`ProjectPanelViewModel`、`UseCasesPanelViewModel`、`RequestHistoryPanelViewModel` 等从 `ObservableCollection` 切换到 `BatchObservableCollection`，批量加载时只触发一次 `CollectionChanged`，减少 UI 闪烁。
