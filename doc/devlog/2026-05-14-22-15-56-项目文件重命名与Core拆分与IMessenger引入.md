# 项目文件重命名与 Core 拆分与 IMessenger 引入

## 本次目标

从项目架构层次消除三个长期技术债务：
1. 主项目文件名仍为历史旧名 `Apifox.App.csproj`
2. 所有层耦合在单一项目中
3. ViewModel 间通信通过 40+ 委托回调

## 核心改动

### 任务 1：重命名 csproj
- `Apifox.App.csproj` → `ApixPress.App.csproj`
- 同步更新 slnx、test csproj、release.yml、package.ps1

### 任务 2：拆出 ApixPress.Core 项目
- 新建 `src/ApixPress.Core/`，仅依赖 `Azrng.Core` NuGet
- 移动 58 个文件：10 Entity + 26 DTO + 8 Repository Interface + 14 Service Interface
- 保留 `IWindowHostService`、`IAppNotificationService`（引用 Avalonia）在 App 中
- 保持原有命名空间不变，零 using 修改

### 任务 3：引入 IMessenger
- 在 Core 项目定义 6 个消息类型：`WorkspaceStateChangedMessage`、`StatusMessageRequest`、`BusyStateChangedMessage`、`NavigationRequestMessage` 等
- `ProjectTabHostContext` 从 10 个委托简化为 3 个属性（2 个 Func<> 查询 + IMessenger）
- `ProjectTabWorkspaceContext` 从 8 个委托简化为 6 个 Func<> 查询
- `ProjectTabViewModel` 实现 `IRecipient<T>` 处理所有消息
- 10 个子 ViewModel 从 Action 委托迁移到 `_messenger.Send()`
- 每个 ProjectTab 拥有独立 `WeakReferenceMessenger`，避免跨 Tab 消息干扰
